# Injili Milele

Bilingual (Kiswahili / English) library of articles, books, video, audio and links with a
digital store, used by the **Imani za Msingi** and **SDA Fundamental Beliefs** apps.

- Kiswahili: https://almodad-2.github.io/injili-milele/sw/
- English: https://almodad-2.github.io/injili-milele/en/
- The old address (`/makala-maalum/`) redirects here (repo `Almodad-2/makala-maalum`).

The site is plain static HTML generated by `build.py` into `docs/`, which GitHub Pages serves.

## Build

```bash
python3 build.py                              # rebuild docs/ (no dependencies)
.venv/bin/python build.py --pdf               # regenerate every PDF, preview and page thumbnail
.venv/bin/python build.py --pdf a-pambano-kuu # ...or only some (product ids)
.venv/bin/python build.py --upload            # upload changed PDFs/audio to the payments KV store
```

`--pdf` needs Google Chrome and PyMuPDF (`python3 -m venv .venv && .venv/bin/pip install pymupdf`).
Then commit and push. Pages updates in about a minute.

## How the library works

Every text article is published as a **designed PDF** (A5, cover, running header, page numbers,
"more from Injili Milele" back page) instead of web text. Video and audio items keep their media;
a video article with a long text also gets a PDF. Links open the external page.

Each PDF/audio item is automatically a product (`a-<slug>`) and **starts free**. In the dashboard
(*Prices & Library*) give it a price to sell it:

| Dashboard | Reader sees |
| --- | --- |
| price 0 | the whole PDF in the page + Download |
| price > 0, *Free preview* on | the first pages (about 30%), then "Buy the full PDF" |
| price > 0, *Free preview* off | cover, contents, sample pages and the buy button |

Files are never public: the Worker's `GET /read/<id>` serves the full file only while the item is
free, the preview while it is priced, and paid copies through signed `/dl/` links after payment.
Generated files live in `store-private/pdf/` and `store-private/preview/` (gitignored).

## Add an item

Create `content/articles/sw/<slug>.html` (or `en/`). It starts with a JSON header:

```html
<!--
{
  "lang": "sw", "slug": "jina-la-makala", "pair": "09", "order": 0,
  "title": "Kichwa cha Makala", "category": "Sabato",
  "author": "Pr. Almodad Amos Yaragwiller",
  "image": "9c567f468b", "card": "9c567f468b",
  "excerpt": "Muhtasari mfupi…", "words": 1200
}
-->
<p>Aya ya kwanza…</p>
<h2>Kichwa kidogo</h2>
<blockquote class="bible"><p>“Andiko…”</p><cite>Yohana 3:16</cite></blockquote>
<blockquote class="spirit"><p>Nukuu ya Roho ya Unabii…</p><cite>Desire of Ages, uk. 759</cite></blockquote>
```

- `order`: position in the library (0 = top, featured). `pair`: same value links SW/EN translations.
- `image`/`card`: an image name (without `.jpg`) in `assets/img/`. `"kind": "book"` labels it a book.
- **PDF you already have**: put it in `content/files/` and add `"pdfFile": "name.pdf"` (sold as is;
  the preview is its first pages). Otherwise the PDF is typeset from the HTML body.
- **Video**: `<div class="video" data-yt="YOUTUBE_ID" data-title="Title"></div>` in the body.
- **Audio**: `"format": "audio", "audio": "name.mp3"` with the file in `content/files/` (max 25 MB).
- **Link**: `"format": "link", "url": "https://…"`.

Then: `.venv/bin/python build.py --pdf <a-slug> --upload`, commit and push. New items are free
until a price is set in the dashboard.

## Store

Collections (bundles) live in `content/products.json` (prices in TZS; `{n}` = number of articles).
Payment details and contacts live in `content/site.json`.

## Admin dashboard (Firebase)

**https://almodad-2.github.io/injili-milele/admin/** (not linked from the site)

The super admin is `modaofpeace@gmail.com`; it can add more admins in the *Admins* tab.
The backend is the app's Firebase project (`imani-za-msingi-ios`):

| Collection | Purpose |
| --- | --- |
| `store_products/{productId}` | live price, sale price, shown/hidden, delivery link |
| `store_coupons/{CODE}` | discount codes (percent or fixed, expiry, max uses, books) |
| `store_orders/{ref}` | orders sent from the cart (pending → paid → delivered) |
| `store_admins/{email}` | extra admins (managed by the super admin) |

Security rules for these collections are in `firebase/store.rules` (also shown in the
dashboard's *Setup* tab). Paste that block into the project's Firestore rules, just
before the last two closing braces, and publish. Existing app rules are not changed.

Sign in with email + password. If the account only uses Google sign-in, use
"send a password link" on the login page to create a password. To enable the Google
button too, add `almodad-2.github.io` under Firebase Authentication → Settings →
Authorized domains.

Website prices still come from `content/products.json` as a fallback; values set in the
dashboard override them live, with no rebuild needed.

## Pesapal payments (Cloudflare Worker)

`payments/` is a Cloudflare Worker at https://makala-payments.modaofpeace.workers.dev
that sits between the website, Pesapal (API 3.0, live) and the dashboard:

1. Cart → `POST /pay`: the Worker recomputes the price (dashboard prices + discount code),
   creates the Pesapal order and returns the payment page.
2. Pesapal → `GET /ipn` and the thank-you page → `GET /status`: the Worker confirms the
   payment with `GetTransactionStatus`, marks it paid and emails the buyer and the admin (Brevo).
3. Downloads: `GET /dl/<token>` serves PDFs from Cloudflare KV through signed links valid 7 days.
4. Dashboard: `GET /admin/sync` (Firebase ID token of an admin) copies paid orders into
   Firestore; `GET /admin/links` makes download links for "Send books".

Secrets (in Cloudflare, never in git): `PESAPAL_CONSUMER_KEY`, `PESAPAL_CONSUMER_SECRET`,
`LINK_SECRET`, `BREVO_API_KEY`. Deploy with `cd payments && npx wrangler deploy`.

After regenerating PDFs, `.venv/bin/python build.py --upload` pushes only the files that changed
(`pdf:<id>` = full file, `preview:<id>` = free preview).
